# ADR-0003：PostgreSQL 作为业务事实源

- 状态：接受
- 日期：2026-07-30
- 决策人：技术负责人

## 背景

平台同时需要事务数据、全文检索、向量检索、缓存和文件存储。若搜索索引或缓存成为事实源，容易出现状态不一致、数据不可恢复和审计链断裂。

## 决策

- PostgreSQL 保存招聘任务、规则版本、业务状态、人工确认、执行记录、连接器状态和审计索引等权威数据。
- OpenSearch 保存可重建的简历与知识检索索引，不直接承载业务状态更新。
- Redis 只用于缓存、限流、分布式锁和短期协调，不保存唯一业务事实。
- MinIO 保存原始文件和派生文件，数据库保存对象标识、摘要、版本和权限元数据。
- 数据库变更与索引事件通过事务内 Outbox 保证最终一致性。

## 结果

缓存和索引损坏后可以从数据库和对象存储重建，关键状态具有单一权威来源。系统需要实现索引重放、对账和失败补偿工具。

## 备选方案

- 只使用 PostgreSQL：首期简单，但难以满足大规模中文全文与混合检索。
- OpenSearch 同时保存业务状态：写入事务和审计一致性较弱。

## 复审条件

客户指定的国产数据库成为强制约束时，保持事实源原则不变，通过兼容层评估替换 PostgreSQL。
