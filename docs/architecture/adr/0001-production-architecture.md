# ADR-0001：采用模块化单体业务核心与独立 AI 服务

- 状态：接受
- 日期：2026-07-30
- 决策人：产品与技术负责人

## 背景

首个生产试点需要同时完成招聘业务闭环、客户系统集成、知识检索和模型调用。此时领域边界仍会变化，如果立即拆分大量微服务，会增加接口协调、部署、数据一致性和故障排查成本。

## 决策

- 招聘任务、岗位方案、候选人、面试、评价、知识元数据、连接器配置和审计入口先放在一个 Spring Boot 模块化单体中。
- 模块之间通过明确的应用服务和领域事件协作，禁止跨模块直接修改数据库表。
- 文档解析、向量化、检索编排、模型调用和证据提取放入独立 FastAPI AI 服务。
- 耗时任务使用消息队列和持久化执行记录异步处理，对外操作必须支持幂等和补偿。

## 结果

首期可以共享事务、统一权限和快速调整领域模型，同时把依赖 GPU、模型和 Python 生态的能力隔离。未来只有在团队、发布节奏、性能或合规边界明确时才拆分业务模块。

## 备选方案

- 全量微服务：边界尚未稳定，首期成本和故障面过大。
- 全部使用 Python：不利于复杂业务事务、企业权限和客户 Java 生态集成。
- 全部放入 Java 服务：模型与文档处理迭代效率较低，依赖隔离困难。

## 复审条件

单模块需要独立扩容、独立发布或独立数据合规边界；单体部署无法满足明确的性能目标；开发团队能够按领域长期独立负责。
