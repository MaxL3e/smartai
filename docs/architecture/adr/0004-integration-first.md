# ADR-0004：API 与事件连接器优先，RPA 仅作为受控兜底

- 状态：接受
- 日期：2026-07-30
- 决策人：产品、实施与技术负责人

## 背景

不同央企使用不同招聘系统，部分系统接口完整，部分只有文件交换或页面操作能力。若把页面自动化作为主要集成方式，会受到页面改版、登录策略、验证码和浏览器环境影响。

## 决策

连接器优先级依次为：

1. 标准 API 与 Webhook。
2. 客户数据库只读视图、消息总线或受控文件交换。
3. 定时增量同步。
4. 经过客户授权的 RPA 页面操作。

所有连接器对内部暴露统一领域接口，并声明能力矩阵、认证方式、限流、幂等、重试和补偿策略。RPA 必须具备步骤日志、截图、人工接管和变更告警，且不得用于绕过客户权限或安全控制。

## 结果

核心产品不依赖某一招聘系统页面结构，客户差异集中在适配层。RPA 可以支持缺少接口的试点，但需要更高的运维和验收成本。

## 备选方案

- 每个客户直接修改核心代码：上线快，但无法形成可维护产品。
- 只支持标准 API：产品最干净，但会排除大量存量系统客户。

## 复审条件

连接器能力模型无法覆盖新的客户集成方式，或 RPA 运维成本持续高于开发正式接口的成本。
