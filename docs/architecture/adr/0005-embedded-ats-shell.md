# ADR-0005：以跨域 iframe 与 Embed SDK 交付 ATS 嵌入插件

- 状态：接受
- 日期：2026-07-30
- 决策人：产品与技术负责人

## 背景

产品需要嵌入不同技术栈和安全策略的客户 ATS。宿主可能是 Angular、Vue、React 或传统服务端页面，且由不同厂商维护。我们需要复用客户登录和岗位/候选人上下文，同时避免依赖冲突、样式污染、敏感数据泄露和双方发布耦合。

## 决策

- 使用跨域 iframe 作为 UI、运行时和数据隔离边界。
- 提供轻量 Embed SDK 管理容器、一次性引导令牌、宿主上下文、MessageChannel、导航和主题。
- ATS 后端通过 OAuth 2.0 Token Exchange 或受信用户断言创建短时、单次嵌入凭据；iframe 令牌只存内存且不依赖第三方 Cookie。
- UI 消息协议只负责宿主协作，不能绕过业务 API、权限、人工门禁和幂等控制。
- 支持 Web Component 包装 SDK，但组件内部仍使用 iframe。
- 保留独立生产入口和独立演示入口作为重新认证、管理和故障降级形态。

## 结果

前端可独立发布并兼容不同 ATS 技术栈，宿主只能通过版本化协议传入有限上下文。客户需要配置精确 Origin、CSP、SSO 断言和导航适配；平台需要维护 Embed SDK、协议兼容和宿主测试壳。

## 备选方案

- 直接注入 React 或 Module Federation：运行时、依赖、路由和发布周期耦合，不作为跨客户默认方案。
- 仅使用 Web Component + Shadow DOM：可隔离样式，但不能提供足够的身份和数据安全边界。
- 浏览器扩展：部署和升级受浏览器管理策略影响，仅作为客户书面批准的兜底。
- 只提供独立站：无法满足 HR 在 ATS 当前上下文内完成工作的目标。

## 复审条件

客户提供统一且稳定的原生微前端扩展协议；iframe 被强制安全策略阻断；浏览器平台能力发生重大变化；或宿主协作需求超过版本化消息协议能够安全承载的范围。
