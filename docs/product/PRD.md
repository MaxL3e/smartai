# 知聘招聘智能体平台产品需求文档

> 文档状态：产品基线  
> 目标阶段：生产试点 MVP  
> 适用范围：央企、国企及其所属单位的社会招聘、校园招聘和内部竞聘  
> 关联文档：[招聘任务工作流](./workflow.md)

## 1. 文档目的

本文将当前“知聘”前端演示验证过的业务路径，转化为可设计、开发、测试和审计的生产产品基线，用于统一产品、研发、算法、实施、安全、法务和试点客户对边界与验收标准的理解。

演示版本中的本地数据和静态模型结果仅用于说明交互。历史原型中的模拟面试回收与综合评分已经停用；生产实现必须由服务端状态、真实接口、版本化知识、固定评分规则和完整审计记录驱动。

## 2. 产品背景与定位

央国企通常已有 ATS、人才库、在线面试、消息、OA 和审批系统，但不同企业的产品与接口差异较大。招聘人员仍需跨系统重复完成需求整理、JD 编写、简历搜索、候选人筛选、面试邀约、结果汇总和材料留档。

知聘当前作为可独立使用的受控招聘智能体运行：以招聘任务为主线，以企业知识和候选人原始证据为依据，以人工决策门禁为边界。HR 可直接维护知识、导入候选简历并完成岗位方案、人才匹配、名单确认和推荐报告。

ATS 与在线面试平台不是当前实现主线。系统保留 Embed SDK、连接器契约、外部资源引用和事件回调扩展点；只有独立智能体核心闭环通过验收后，才启动客户系统适配。

## 3. 产品原则

1. **人工掌握决定权**：岗位发布、评分标准、候选名单、淘汰与推进、录用和 Offer 均由有权限人员确认。
2. **证据先于结论**：推荐、评分和风险项必须关联原始证据、规则版本和知识版本。
3. **规则与模型分离**：模型负责理解、检索和证据提取；硬条件与最终分数由可配置、可测试的固定规则计算。
4. **知识独立治理**：知识库独立维护；工作台仅呈现任务、待办和运行动态，业务页面按需展示引用来源。
5. **外部动作可控**：写入客户系统或联系候选人的动作必须具备权限校验、幂等、重试、补偿和审计能力。
6. **默认保护隐私**：按最小必要原则处理候选人数据，不使用与岗位无关的敏感属性做判断。
7. **可替换、可部署**：模型、检索引擎和连接器可替换，支持客户专有云或本地化部署。
8. **独立闭环优先、接口长期稳定**：当前先保证独立工作台完整可用；外部系统通过版本化契约接入，不反向侵入智能体核心领域。

## 4. 产品目标与非目标

### 4.1 目标

- 跑通“需求创建 -> 岗位方案 -> 知识引用 -> 简历导入 -> 人才匹配 -> 名单确认 -> 推荐报告”的独立真实闭环。
- 减少重复检索、整理、提醒和报告草拟，缩短首次推荐和面试协同时间。
- 让每项推荐都能回答“依据什么规则、引用哪段原文、使用哪个版本的企业知识”。
- 形成稳定的输入输出契约，为后续 ATS、人才库和在线面试系统接入降低定制成本。
- 提供完整权限、审计、数据安全和模型治理能力，并形成可度量的试点结果。

### 4.2 非目标

- 不建设完整 ATS，不承担招聘门户、Offer 审批、入职办理和员工档案等全套人事功能。
- 不允许模型独立发布岗位、自动淘汰候选人、决定录用或发送 Offer。
- 不以单一“AI 分数”代替招聘人员和用人部门判断。
- 不构建通用低代码智能体平台，首期仅服务招聘执行闭环。
- 不在未经授权时将客户数据用于公共模型训练或跨客户共享。
- 不根据性别、民族、宗教、婚育、健康等受保护属性生成画像或推荐结论。
- MVP 不同时适配所有招聘系统、面试工具和岗位类型。
- 当前阶段不实施特定 ATS 或在线面试平台适配，不以外部系统联调替代智能体核心能力验收。
- 不通过未授权 DOM 抓取、脚本注入或浏览器扩展绕过 ATS 权限；业务数据必须来自签名上下文和授权接口。

## 5. 用户与权限

### 5.1 角色定义

| 角色 | 主要职责 | 默认数据范围 |
| --- | --- | --- |
| 招聘 HR | 创建任务、审核方案、筛选候选人、协同面试、维护结论 | 本人负责或被授权任务 |
| 招聘负责人 | 审批方案与评分卡、处理异常、确认候选人推进和任务完成 | 所辖组织任务 |
| 用人经理 | 补充需求、会签任职标准、查看候选人证据、给出业务意见 | 被邀请参与任务 |
| 面试官 | 查看必要材料并完成面试评价 | 被分配候选人与批次 |
| 知识管理员 | 上传、复核、发布、停用和归档企业招聘知识 | 被授权知识空间 |
| 系统管理员 | 用户、组织、角色、连接器、模型和系统策略配置 | 租户配置，默认不读简历正文 |
| 审计员 | 查询和导出运行、决策、数据访问及外部写入记录 | 授权组织，只读 |
| 集成服务账号 | 按授权同步岗位、简历、面试状态和结果 | 明确接口与字段范围 |

### 5.2 权限原则

- RBAC 管理角色能力，ABAC 根据组织、任务归属、数据密级和候选人关系控制数据范围。
- 简历正文、联系方式、面试转写和评价结论分别授权；列表权限不等于正文权限。
- 导出、批量下载、外部发送、配置变更和越权尝试均写入审计日志。
- 系统管理员与业务管理员职责分离；高风险配置、批量导出和删除支持双人复核。
- 服务账号使用独立凭据、最小作用域和有效期，不得复用个人账号。
- 候选人数据默认脱敏，只有具备业务必要性和权限时才解密展示。

## 7. 当前核心用户旅程

1. 招聘 HR 在独立工作台通过自然语言描述招聘需求。
2. 智能体展示结构化草案，HR 确认后才创建任务。
3. 智能体引用有效企业知识生成 JD、任职标准、硬条件、评分卡和阈值。
4. 招聘负责人编辑并确认岗位方案。
5. HR 向独立简历库导入候选简历，系统完成解析、版本化和证据定位。
6. 智能体执行硬过滤、检索、重排和固定评分，HR 查看排名、分项分、原文证据和待核实项。
7. HR 或招聘负责人保存推荐名单，系统生成版本化推荐报告并保留审计记录。

在线面试批次、邀请、提醒、结果回收、综合评价以及 ATS 回写属于未来集成旅程，当前仅保留数据模型、接口契约和页面位置。

详细状态和异常规则见 [招聘任务工作流](./workflow.md)。

## 8. 核心用户故事

### 8.1 当前 MVP P0

- 招聘 HR 可直接描述需求，由系统整理成可核对草案，减少固定表单录入。
- 招聘负责人可编辑并确认 JD、任职标准、评分卡和阈值，确保执行标准已批准。
- 招聘 HR 可查看候选人的分项分和简历原文，而不是只看到总分。
- 招聘 HR 可调整检索阈值和权重后重新运行，并比较不同结果版本。
- 知识管理员发布的知识才参与检索，并可查看版本和引用任务。
- 审计员可追溯结论使用的规则、知识、证据、模型和人工修改。

### 8.2 未来集成目标

- 招聘负责人确认名单后系统才发送面试邀请，避免未经授权联系候选人。
- 招聘 HR 可查看邀请、作答、到期和结果回收状态，并处理失败和补发。
- 招聘负责人可查看固定公式综合评价，并逐人给出人工结论。
- 系统管理员可独立配置、测试、停用连接器并监控同步失败。
- 招聘 HR 可从 ATS 当前岗位或候选人一键进入正确上下文，无需二次登录和重复选择对象。
- 招聘 HR 可在侧栏与全页工作区之间切换并返回原 ATS 位置，不丢失服务端状态或重复提交命令。

### 8.3 P1

- 用人经理可在岗位方案和候选名单节点会签，不必拥有全部招聘权限。
- 招聘 HR 可复制历史任务和岗位方案，复用已验证标准。
- 招聘负责人可比较智能体推荐和人工结论，持续调整评分标准。
- 知识管理员可收到知识到期、冲突和高频未命中提示。
- 运营人员可用离线评价集回归测试模型、提示和检索策略后再发布。

## 9. 功能需求

### 9.1 嵌入式交互与宿主上下文

> 本节为 ATS 适配阶段的接口预留，不纳入当前独立智能体 MVP 验收。

- `FR-EMBED-001` 在 ATS 岗位详情、候选人详情/列表和主导航提供一键入口，分别打开上下文侧栏或全页工作区。
- `FR-EMBED-002` 复用客户 SSO；有效 ATS 会话下不得要求用户再次输入账号密码。
- `FR-EMBED-003` 每次启动使用签名且短时有效的 `HostContext`，包含租户、用户、允许作用域、父页面 Origin 以及岗位、任务、申请或候选人外部引用；缺失、过期、篡改或越权时安全失败。
- `FR-EMBED-004` 同一来源系统、岗位和招聘轮次默认只允许一个活动任务；重复唤起恢复原任务，不重复创建。
- `FR-EMBED-005` 侧栏与全页工作区共享服务端状态、资源版本和命令幂等键；切换形态、关闭重开或宿主路由变化不取消后台运行。
- `FR-EMBED-006` 宿主通信使用版本化 SDK 与精确 Origin 的消息白名单，不广播联系方式、简历正文、面试转写或业务写入正文。
- `FR-EMBED-007` 支持白名单主题令牌、宿主能力协商、返回宿主页、会话续期、协议兼容提示和独立打开降级。
- `FR-EMBED-008` 知识维护只在授权的全页管理区开放；岗位和候选人侧栏仅展示当前任务引用和来源。

### 9.2 招聘任务与岗位方案

- `FR-TASK-001` 支持自然语言输入并提取岗位、部门、地点、人数、招聘类型、优先级、计划时间、核心要求和知识范围。
- `FR-TASK-002` 未识别或低置信度字段必须明确标记；默认值必须展示，不得隐式确认。
- `FR-TASK-003` 只有用户确认草案后才创建任务并分配全局唯一编号。
- `FR-TASK-004` 记录负责人、参与人、组织、阶段、执行状态、期限、数据来源和版本。
- `FR-TASK-005` 支持搜索、筛选、编辑、复制、暂停、恢复、取消、归档和恢复归档，并校验状态及权限。
- `FR-PLAN-001` 基于需求和已发布知识生成 JD、任职标准、硬条件、评分卡、阈值和知识引用。
- `FR-PLAN-002` 生成内容可编辑，人工修改与模型原稿以差异版本留存。
- `FR-PLAN-003` 权重总和必须为 100%，区间连续不重叠，硬条件与加分项分开配置。
- `FR-PLAN-004` 确认时固化方案、规则、提示和知识版本；后续修改生成新版本，不覆盖历史依据。
- `FR-PLAN-005` 未确认方案时不得启动人才检索或发送候选人邀请。

### 9.3 人才匹配

- `FR-MATCH-001` 检索范围只能来自客户授权的人才库、岗位和时间范围。
- `FR-MATCH-002` 顺序为硬条件过滤、混合召回、重排、证据提取、固定规则评分和结果质检。
- `FR-MATCH-003` 每项得分关联原文、位置、文档版本和置信度；信息不足标记“待核实”，不得推断。
- `FR-MATCH-004` 列表展示总分、等级和关键依据，详情展示规则、证据、推荐依据、待核实项和画像来源。
- `FR-MATCH-005` 用户可调整最低分、权重、检索范围和排序后重新运行，历史结果版本保持可查。
- `FR-MATCH-006` 不得仅因模型低分自动淘汰；硬条件排除必须展示规则和来源字段。
- `FR-MATCH-007` 确认名单至少选择一人，由有权限人员确认并生成名单版本。

### 9.4 面试协同与综合评价

> 本节为在线面试和评价阶段的能力预留，当前页面不发送邀请、不回收结果，也不生成模拟评分。

- `FR-INT-001` 名单确认后按配置创建批次、邀请、截止时间和候选人级记录。
- `FR-INT-002` 外部发送使用幂等键；超时或结果未知时先查询下游，不得直接重复发送。
- `FR-INT-003` 支持待发送、已发送、已送达、进行中、已完成、已过期、已拒绝、已取消和异常状态。
- `FR-INT-004` 支持提醒、调整截止时间、取消和人工补录，记录操作者与原因。
- `FR-INT-005` 结果与转写校验来源、完整性、候选人映射和版本后入库。
- `FR-INT-006` 至少一人完成面试后才可生成其综合评价。
- `FR-EVAL-001` 综合分由已发布规则计算，模型只提取证据和草拟说明。
- `FR-EVAL-002` 分别展示简历、在线面试、测评和人工评价的分数、权重、来源与原文。
- `FR-EVAL-003` 风险项区分事实不一致、证据不足和待追问，不把不确定信息表述为事实。
- `FR-EVAL-004` 有权限人员逐人选择“进入下一轮”“保留复核”或“不进入”并可填写理由。
- `FR-EVAL-005` 修改已确认结论须生成修订版本，保留原结论、修改人、原因和时间。
- `FR-EVAL-006` 支持导出脱敏报告并按授权回写客户 ATS。

### 9.5 知识、工作台与审计

- `FR-KB-001` 支持岗位知识、人才画像、制度流程及可扩展分类。
- `FR-KB-002` 支持文件校验、病毒扫描、OCR/解析、切分、标签、有效期、负责人和权限范围。
- `FR-KB-003` 新知识默认待复核，只有已发布版本可参与智能体检索。
- `FR-KB-004` 支持草稿、待复核、可用、停用、归档，以及版本对比、恢复和引用影响分析。
- `FR-KB-005` 画像只使用岗位相关的能力、经验和行为证据，不包含受保护属性或代理变量。
- `FR-KB-006` 业务页面按需展示引用；工作台不重复展示知识资料列表。
- `FR-OPS-001` 工作台展示任务阶段、本轮产出、待确认、真实运行动态、失败状态和处理入口。
- `FR-OPS-002` 待办包含任务、动作、发起人、截止时间、超时状态和直达入口。
- `FR-OPS-003` 通知支持站内及客户启用渠道，并支持已读、订阅、频率和超时升级。
- `FR-OPS-004` 审计包含租户、组织、用户/服务账号、任务、动作、输入/输出摘要、对象、知识/规则/模型版本、外部请求标识、时间和结果。
- `FR-OPS-005` 审计防篡改、可检索、授权导出且敏感内容脱敏；业务用户不能删除。
- `FR-OPS-006` 实时动态必须反映服务端事件，不得用前端动画伪造生产状态。

### 9.6 集成与模型治理

- `FR-ADM-001` 连接器提供认证、字段映射、连通测试、限流、超时、重试、熔断、死信和健康状态。
- `FR-ADM-002` 外部读写记录业务键、幂等键、请求/响应摘要和最终一致性状态。
- `FR-ADM-003` 模型输出符合 JSON Schema；失败时有限修复或人工处理，不将自由文本直接写入核心字段。
- `FR-ADM-004` 模型、提示、检索和评分规则版本化，经离线评价及审批后发布。
- `FR-ADM-005` 支持 OIDC/SAML/LDAP，并遵守客户会话、多因素认证策略。
- `FR-ADM-006` 支持外部模型、私有模型或按客户策略禁用部分 AI 能力。

## 10. 人工决策边界

| 动作 | 智能体可自动执行 | 必须人工确认 | 禁止行为 |
| --- | --- | --- | --- |
| 需求整理 | 提取字段、提示缺失、生成草案 | 确认创建任务 | 隐式填关键条件并执行 |
| 岗位方案 | 草拟 JD、标准和评分卡 | 确认方案、岗位发布 | 未审批直接发布 |
| 人才检索 | 检索、排序、证据提取、规则计分 | 确认候选名单 | 仅凭模型自动淘汰 |
| 面试协同 | 名单确认后邀请、提醒和回收 | 名单、取消、特殊补发 | 未经确认联系候选人 |
| 综合评价 | 汇总证据、固定公式、草拟报告 | 推进、保留、淘汰和录用意见 | 模型冒充人工结论 |
| 知识治理 | 解析、分类、发现冲突和到期 | 发布、停用、敏感内容处理 | 未复核知识进入检索 |
| 外部写入 | 执行已授权的幂等写入 | 高风险或客户要求的审批 | 绕过客户审批链路 |

界面和 API 必须区分“模型建议”“规则计算结果”“系统状态”和“人工结论”。

## 11. 非功能需求

### 11.1 安全、隐私与合规

- `NFR-SEC-001` 全程 TLS，敏感数据存储加密，密钥由专用服务托管并轮换。
- `NFR-SEC-002` 候选人数据按目的、组织、任务和有效期最小化，支持删除、匿名化、冻结和保留策略。
- `NFR-SEC-003` 日志不得记录完整简历、联系方式、面试转写、密钥或原始敏感提示。
- `NFR-SEC-004` 支持客户等保、分类分级、安全审计、漏洞和备份要求。
- `NFR-SEC-005` 外部模型数据通过脱敏、字段白名单、租户策略和数据出境检查。

### 11.2 性能、可靠性与可用性

- `NFR-PERF-001` 常规查询 P95 小于 2 秒，保存 P95 小于 3 秒。
- `NFR-PERF-002` 对 10 万份已索引简历，95% 的匹配任务在 5 分钟内产生首批推荐，并显示真实进度。
- `NFR-PERF-003` 试点月可用性不低于 99.5%，正式推广目标不低于 99.9%。
- `NFR-REL-001` 外部写操作幂等；重复、乱序和网络未知状态不得造成重复邀请或状态倒退。
- `NFR-REL-002` 状态迁移使用事务和版本校验，非法迁移返回明确错误并审计。
- `NFR-REL-003` 长任务异步执行，支持检查点、超时、安全取消和不重复处理。

### 11.3 可解释性、观测与体验

- `NFR-AI-001` 推荐分项均有规则和证据；证据不足不得伪造。
- `NFR-AI-002` 模型、提示、知识、检索和评分版本可重建计算上下文。
- `NFR-AI-003` 上线前使用脱敏评价集做准确性、公平性、安全性和回归测试。
- `NFR-OPS-001` 请求、异步任务、模型和连接器调用使用统一追踪标识。
- `NFR-OPS-002` 监控成功率、耗时、积压、重试、人工接管、成本和质量漂移。
- `NFR-UX-001` 在 1280x720、1440x900、1920x1080 宿主视口中，岗位工作台、人才匹配、面试协同和综合评价的页头、当前状态、待确认正文摘要和主操作首屏可见；宿主与 iframe 不得同时纵向滚动，iframe 内最多一个主纵向滚动容器且页面无横向滚动。
- `NFR-UX-002` 自动动作均展示真实状态、结果、失败原因和下一步，不使用装饰性“AI 执行中”。
- `NFR-UX-003` 支持键盘、可见焦点、错误定位和主流浏览器，关键页面满足 WCAG 2.1 AA 基础要求。

## 12. 生产试点 MVP

### 12.1 范围内

- 单一试点企业隔离部署或独立租户，接入统一身份认证。
- 1 至 2 个标准清晰、历史样本充足的岗位族。
- 独立用户入口、组织和权限管理，以及可直接使用的招聘任务工作台。
- 独立简历库的文件导入、解析、版本、检索、匹配与名单确认。
- 全页知识库、招聘任务、人才匹配、推荐报告和审计入口。
- 知识上传、解析、复核、发布、版本、检索和引用追踪。
- 规则过滤、混合检索、重排、证据提取、固定评分和人工确认名单。
- 候选名单确认、证据汇总、推荐报告和人工结论；在线面试邀约与结果回收为后续接口预留。
- 审计、监控、幂等、重试、人工补偿、脱敏和基础运营指标。
- 演示模式与生产模式并存，演示数据不得进入生产租户。

### 12.2 范围外

- 多客户共享的公有云 SaaS 商业化运营能力。
- 同时接入多个 ATS、面试平台或全渠道消息中心。
- Offer 审批、背调、入职和员工生命周期管理。
- 视频情绪、面相、声音性格等缺乏可靠岗位相关性的推断。
- 全岗位族自动迁移、自动学习评分权重和无人值守招聘。
- 将客户简历用于跨客户模型训练。

### 12.3 依赖

- 客户确认试点组织、岗位、角色、流程负责人和验收人员。
- 客户提供合法授权的脱敏历史数据、接口文档、测试账号和网络环境。
- 客户或试点团队提供合法授权的脱敏历史 JD、人才画像和候选简历样本。
- 业务团队定义硬条件、评分卡、人工门禁和结果回写范围。
- 安全与法务确认数据分类、模型使用、保留期限和候选人告知要求。
- 项目组建立人工标注评价集和当前人工流程基线。

## 13. 验收指标

### 13.1 功能与控制

- 主流程 P0 用例通过率 100%，非法状态迁移全部被阻止并明确提示。
- 岗位方案、候选名单、推进/淘汰结论和岗位发布人工门禁覆盖率 100%。
- 已确认评分的规则版本、知识版本和原始证据可追溯率 100%。
- 智能体动作、人工修改、权限拒绝和外部写入审计覆盖率 100%。
- 模型结构化输出 Schema 校验率 100%，无未校验自由文本写入核心字段。

### 13.2 模型与检索

- 硬条件规则在确认评价集上的执行准确率 100%。
- 推荐分项证据覆盖率 100%；无证据项标记待核实且不伪造原文。
- Top 20 岗位相关候选人占比不低于试点人工检索基线，首期目标不低于 70%。
- 关键字段提取准确率不低于 95%，低置信度字段全部进入人工复核。
- 模型、提示、检索或评分升级后，核心评价集不得出现未批准的显著回退。

### 13.3 业务效果

- 确认岗位方案到首批可审核推荐结果的中位时间不超过 10 分钟。
- 相比基线，HR 单岗位首轮筛选和证据整理时间降低至少 50%。
- Top 20 推荐的采纳或保留复核比例达到试点约定目标，首期建议不低于 60%。
- 岗位方案、推荐结果和报告的关键内容人工修改率持续可观测并形成优化闭环。
- 试点期不得发生越权自动淘汰、自动录用、重复邀请或敏感数据泄露严重事件。

具体阈值应在试点启动时按岗位难度、人才库质量和人工基线共同签署，不以演示数据作为生产承诺。

### 13.4 未来集成验收

- 重复提交、超时重试和重复回调场景下，面试邀请重复发送数为 0。
- 岗位页和候选人页一次点击进入正确上下文；上下文绑定准确率与越权阻止率均为 100%。
- 有效 ATS 会话下二次登录次数为 0；侧栏与全页切换、关闭重开后的服务端状态恢复率为 100%，重复业务命令为 0。
- 嵌入壳在约定客户端和网络条件下初始化成功率不低于 99.5%，P95 不高于 3 秒；支持视口满足 `NFR-UX-001`，无内容遮挡或嵌套滚动问题。

本节只在在线面试或 ATS 适配正式排期后启用，不影响当前独立智能体 MVP 的完成度判定。

## 14. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| 历史录用数据带有偏差 | 不直接作为唯一标签；由业务定义岗位相关评价集并做公平性检查 |
| 企业知识过期或冲突 | 发布复核、有效期、负责人、冲突提示、引用固化和影响分析 |
| 模型幻觉或证据错配 | 结构化输出、原文定位、置信度、固定评分、抽样复核、无证据不结论 |
| 客户接口不稳定 | 适配层、幂等键、状态查询、有限重试、熔断、死信和人工补偿 |
| 候选人隐私泄露 | 最小字段、脱敏、细粒度权限、外部模型白名单、导出水印和审计 |
| 用户误把建议当决定 | 区分结果类型，关键节点人工确认，报告保留责任主体 |
| 原型逻辑直接进入生产 | 服务端状态机和 API 契约为唯一事实源，前端不自行推进关键状态 |

## 15. 版本与变更原则

- P0、人工边界和审计要求属于生产基线，变更需产品、业务和安全共同评审。
- 状态机、评分规则、知识、模型策略和连接器契约实行显式版本管理。
- 影响候选人排序、排除或人工决策展示的改动，须通过评价集回归和业务验收。
- 演示交互可持续优化，但不得绕过生产权限、状态和审计约束。
