# 招聘智能体平台 MVP 实施计划

> 计划周期：12 至 16 周  
> 推荐基线：14 周交付试点，预留 2 周客户联调和合规缓冲  
> 试点范围：1 家客户、1 个组织、1 至 2 个岗位族、1 套 ATS/简历库、1 个在线面试工具、1 个消息渠道

## 0. 当前实施顺序

本项目交付的是招聘智能体，不是重新建设一套 ATS。ATS 只负责提供宿主入口、业务上下文和外部系统能力，不能先于智能体核心闭环成为开发主线。

当前实现严格按以下顺序推进：

1. 对话理解招聘需求，生成可追溯、可修改、需人工确认的需求草案。
2. 基于企业知识生成岗位描述、任职标准、评分卡和推荐阈值。
3. 从授权人才数据中检索候选人，提取原文证据并按固定规则评分。
4. 经人工确认名单后调用在线面试、消息等连接器，跟踪并回收结果。
5. 汇总简历、面试和人工意见，生成可复核的综合评价与审计记录。
6. 上述闭环稳定后，通过 Embed SDK 和客户适配器嵌入不同 ATS。

当前 `apps/host-harness/` 仅是集成开发联调工具，不是产品主体，也不得作为智能体功能完成度的替代证明。

## 1. MVP 目标

将现有前端演示升级为可在客户 ATS 内运行的嵌入式产品闭环：HR 从当前岗位或候选人一键进入智能体侧栏或全页工作区，确认岗位方案和评分卡，检索并解释匹配结果，确认名单后发起在线面试，回收结果并生成可复核的综合评价，全过程可追溯、可重试、可人工接管。

MVP 成功不以“模型能生成内容”为标准，而以真实系统集成、稳定评分、人工门禁、安全审计和业务效率提升为标准。

### 范围内

- 多角色登录、组织和岗位范围权限。
- 招聘任务、岗位方案、评分卡、候选匹配、面试协同、综合评价和审计闭环。
- 历史 JD、岗位标准、人才画像和制度资料的上传、解析、检索、版本和引用。
- 一套客户 ATS/简历库、一套在线面试工具和一个消息渠道的真实适配。
- 一个 ATS 宿主适配器、Embed SDK、签名上下文、SSO 会话桥接、岗位/候选人侧栏及 ATS 内全页工作区。
- 固定评分卡、原文证据、模型调用记录、人工确认和异常补偿。
- 私有化或客户认可环境的可重复部署、监控、备份和安全验收。

### 暂不纳入

- 同时支持多个客户生产环境和复杂计费体系。
- 自动决定淘汰、录用或发放 Offer。
- 全量微服务拆分、跨区域多活和大规模模型训练平台。
- 一次性适配所有 ATS、OA、面试和消息供应商。
- 在缺少合法依据时使用历史录用结果训练或推断敏感属性。
- 以独立站替代 ATS 嵌入完成生产 UAT；独立站只用于演示、管理和受控降级。

## 2. 阶段路线图

| 阶段 | 周期 | 目标 | 主要产出 | 阶段门禁 |
| --- | --- | --- | --- | --- |
| 0. 试点立项 | 第 1 周 | 锁定客户、岗位和数据边界 | 试点章程、RACI、成功指标、数据与接口清单 | 客户业务、IT、安全负责人共同确认 |
| 1. 产品与架构基线 | 第 2 至 3 周 | 固化状态机、领域模型和契约 | PRD、流程、权限矩阵、API 契约、部署设计、评价集方案 | 关键流程无未决责任边界，接口可获得性已验证 |
| 2. 平台底座 | 第 4 至 6 周 | 建立可运行、可审计的后端基础 | 认证、租户/组织、任务 API、数据库、对象存储、队列、审计、CI/CD | 测试环境可部署，核心资源契约测试通过 |
| 3. 知识与人才匹配 | 第 7 至 9 周 | 跑通知识处理和可解释推荐 | 文档解析、混合检索、重排、评分卡、证据链、人工确认 | 离线评价集达标，推荐可逐项追溯原文 |
| 4. 面试与外部闭环 | 第 10 至 11 周 | 跑通邀约、状态回收和综合评价 | 面试/消息适配器、Webhook、重试补偿、评价报告 | 测试候选人闭环成功，重复调用不产生副作用 |
| 5. 安全、UAT 与试运行 | 第 12 至 14 周 | 完成客户验收并进入受控试运行 | 安全测试、性能测试、UAT、运维手册、培训、试运行报告 | P0/P1 缺陷清零，高危安全问题清零 |
| 6. 缓冲与上线 | 第 15 至 16 周（可选） | 消化客户依赖并完成上线决策 | 遗留修复、数据对账、上线/回退方案、复盘 | 业务、IT、安全三方签署 Go/No-Go |

若必须压缩至 12 周，应减少 OA 集成、RPA 兜底和高级知识运营能力，不得压缩权限、脱敏、人工门禁、审计和幂等验证。

| E10-05 | P0 | 制定上线、回退、备份恢复和应急预案 | 客户运维 | 演练通过，RTO/RPO 和联系人明确 |
| E10-06 | P0 | 试运行、指标复盘和 Go/No-Go | E10-01 至 E10-05 | 试运行报告完成，业务、IT、安全三方签署结论 |
| E10-07 | P0 | 完成嵌入兼容与攻击场景测试 | E02-07、E03-06 | 覆盖伪造 Origin、消息/令牌重放、点击劫持、三方 Cookie 禁用、宿主卸载和独立页降级 |

## 4. 关键依赖与里程碑

### 客户必须按时提供

- 第 1 周：业务负责人、ATS 产品/前端负责人、接口负责人、安全负责人和试点用户。
- 第 2 周：ATS 测试宿主壳、扩展文档、允许 Origin、CSP、SSO、主题、对象 ID/URL 规则、浏览器管理策略、脱敏样本和字段字典。
- 第 3 周：ATS/简历库和面试系统沙箱、服务账号及测试候选人。
- 第 6 周：客户测试环境网络连通、证书、域名和日志接入方式。
- 第 10 周：UAT 用户、验收脚本确认和生产变更窗口。

若接口沙箱、合法数据或安全结论晚于门禁日期，不应通过加班掩盖依赖，应立即缩小集成范围或调整里程碑。

### 核心里程碑

| 里程碑 | 目标周 | 可演示的真实结果 |
| --- | --- | --- |
| M1 方案冻结 | 第 3 周 | 使用脱敏数据走完目标流程，宿主形态、领域模型和接口责任明确 |
| M2 平台可用 | 第 6 周 | 用户从真实 ATS 岗位/候选人页单点进入侧栏，并在同一 ATS 壳内打开全页工作区完成任务操作 |
| M3 推荐可验 | 第 9 周 | 从真实等价简历库得到有证据、可复算的推荐结果 |
| M4 闭环打通 | 第 11 周 | 人工确认后发送面试并自动回收结果和状态 |
| M5 试点验收 | 第 14 周 | UAT、安全、性能和运维验收通过，开始受控试运行 |

## 5. 全局 Definition of Done

任何 P0 能力只有同时满足以下条件才可标记完成：

1. 产品验收标准和异常路径已实现，不只有理想流程。
2. API、数据迁移、权限和审计设计已评审，OpenAPI 文档同步更新。
3. 单元和集成测试通过；关键用户流程有 Playwright 或等价端到端测试。
4. 敏感字段已分类、脱敏和最小化，日志中无简历正文和明文联系方式。
5. 外部写操作具有幂等、超时、重试、人工补偿和对账能力。
6. AI 输出经过 Schema 校验，结果可追溯模型、提示、知识、简历和评分卡版本。
7. 已配置关键指标、追踪和告警，并有故障处理责任人。
8. 文档、操作手册和回退方式完成；指定业务用户已验收。

## 6. 验收指标

### 业务效果

| 指标 | MVP 目标 | 测量方法 |
| --- | --- | --- |
| 单岗位首次筛选用时 | 比现状降低至少 50% | 同岗位族试点前后对比，中位数统计 |
| Top 20 岗位相关率 | 不低于 70%，且不低于试点人工检索基线 | HR 在隐藏来源和排序的情况下判断候选人与岗位是否相关 |
| Top 20 采纳或保留复核比例 | 首期建议不低于 60% | HR 在真实流程中选择进入下一步或保留复核的比例 |
| 推荐解释覆盖率 | 100% | 每个评分项有原文证据或明确标记“无证据” |
| 人工修改率 | 建立基线并逐周下降 | 记录 AI 草稿到确认版本的字段差异 |
| 面试邀请处理成功率 | 不低于 99% | 排除候选人主动拒绝后的技术成功率 |
| ATS 嵌入体验 | 上下文准确率 100%，有效会话二次登录 0 次 | 岗位/候选人入口、关闭重开、侧栏/全页切换和宿主前进后退 E2E |

### 模型与检索质量

| 指标 | MVP 目标 |
| --- | --- |
| 硬性条件过滤准确率 | 100% |
| 结构化输出可解析率 | 不低于 99.5%，其余自动重试或转人工 |
| 引用定位正确率 | 抽检不低于 95%，关键否决项必须 100% 人工复核 |
| 固定评分可复算率 | 100% |
| 敏感属性直接或代理评分项 | 0 个；合规审批只能用于检测、审计和纠偏，不能放行评分 |

### 工程与安全

| 指标 | MVP 目标 |
| --- | --- |
| 试点月度可用性验收 | 不低于 99.5%；架构设计目标 99.9% |
| 常规查询/保存 P95 | 不高于 2 秒 / 3 秒 |
| 10 万份已索引简历首批推荐 | 95% 在 5 分钟内完成，展示真实进度 |
| 岗位方案确认到首批可审结果 | 中位时间不高于 10 分钟 |
| 关键字段提取准确率 | 不低于 95%，低置信度全部人工复核 |
| 嵌入壳初始化 | 有效会话下成功率不低于 99.5%，P95 不高于 3 秒；独立页降级成功率 100% |
| 宿主布局 | 1280x720、1440x900、1920x1080 下核心状态和主操作首屏可见；宿主/iframe 不双纵向滚动，页面无横向滚动 |
| 关键状态最终一致率 | 不低于 99.9% |
| 外部写操作幂等率 | 100% |
| 审计事件完整率 | 100% |
| P0/P1 缺陷 | 上线前 0 个未关闭 |
| 高危安全问题 | 上线前 0 个未关闭 |
| 备份恢复 | 达到客户确认的 RTO/RPO 并完成演练 |

验收数字应在第 2 周根据客户真实基线确认；未经基线测量，不以单一“模型准确率”作为上线依据。

## 8. 主要风险与应对

| 风险 | 影响 | 预警信号 | 应对与责任 |
| --- | --- | --- | --- |
| 客户接口或沙箱延期 | 集成闭环无法按时验证 | 第 2 周仍无字段文档或账号 | 交付经理升级；使用契约 Mock 并明确日期，必要时缩减 OA/RPA 范围 |
| ATS 无稳定扩展点或安全策略阻断嵌入 | 无法在客户主工作流 UAT | 第 2 周仍无测试宿主、Origin/CSP 或扩展授权 | 按原生扩展、iframe、受管浏览器插件决策；无书面可行方案则 No-Go，独立站不能替代验收 |
| 历史数据质量差或授权不清 | 推荐评价失真、合规受阻 | 简历重复、缺字段、无处理依据 | 产品与安全先做数据盘点；建立质量报告和最小数据集 |
| 模型结论缺乏证据 | HR 不信任，存在决策风险 | 自由分数、引用错位、重复运行漂移 | 固定评分、证据定位、版本锁定、低置信度转人工 |
| 历史录用偏差被固化 | 对候选人不公平 | 某些非岗位因素与得分强相关 | 禁用敏感属性及代理变量；公平性评审和定期抽检 |
| 外部调用重复或状态不一致 | 重复邀请、错误阶段、候选人投诉 | 超时后盲重试、Webhook 乱序 | 幂等键、版本控制、调用前查询、对账和死信补偿 |
| 前端演示逻辑直接进入生产 | 状态不可控、维护成本高 | 继续依赖 `localStorage` 和单文件状态 | 建立领域 API 与双模式适配，按模块逐步迁移 |
| 私有化环境资源不足 | 检索和模型延迟不可用 | 无 GPU/存储估算、网络隔离未验证 | 第 2 周容量评估；模型可替换、异步化和降级策略 |
| RPA 页面变化 | 关键流程中断或误操作 | 选择器频繁失败、登录验证变化 | 仅低频受控使用，失败即停、截图审计、人工接管和 API 退出计划 |
| 范围持续膨胀 | 14 周无法形成可用闭环 | 新增多客户、多渠道和复杂审批 | 变更委员会按成功指标取舍，P2 不进入试点关键路径 |
| 用户不采用 | 技术通过但业务价值未形成 | HR 绕过平台、人工修改率居高 | 每两周参与式评审，培训和指标复盘，优先修正工作流摩擦 |

## 9. 治理节奏

- 每日：工程站会，更新阻塞、接口失败和安全问题。
- 每周：产品、架构、数据和客户依赖评审，演示可运行增量。
- 每两周：里程碑验收和 Backlog 重排，只允许一个试点关键路径。
- 每月：模型质量、公平性、成本和审计完整性复盘。
- 上线前：业务、IT、安全三方 Go/No-Go 评审；任何一方否决均不得生产放量。

项目状态必须基于可运行环境、自动化结果和客户证据更新，不以文档完成度或页面完成度代替真实进展。
